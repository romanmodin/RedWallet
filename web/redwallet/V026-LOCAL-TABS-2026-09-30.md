# RedWallet 0.26 local wallet tabs — reviewed source

After unlocking a local encrypted wallet, Home and Activity use that same
account's validated saved scan and signed receipts. Unrelated demo balances
are no longer shown in those tabs while a local account is selected. Pending
signed payments link back to the existing Send confirmation controls; historical
sent receipts include signed recipient, amount, fee and transaction ID. Unknown
account history amounts/directions/times remain explicitly unavailable.

Send and Receive reuse the reviewed CSP-gated workspace. Navigation destroys
the old vault controller session and payment review; new workspaces start
locked while restoring the authenticated public selection, completed scan and
unsigned draft. Receive omits payment controls. Send omits the long account
history list, which now has its own Activity view. Navigation itself performs
no account discovery or payment submission. Wallets remains the place to
refresh recovery scans, create/recover, or switch to watched/demo accounts.

The selection contains public account data only and lives in the current tab's
React provider. It never owns secrets/controllers or persists plaintext key
material. A full page reload still requires unlocking the same vault once;
the completed scan and draft restore afterward. Cross-tab vault invalidation
clears the selected account. Existing archives and public scan formats are
unchanged. Cached balances are last-scan observations; fresh coins, raw parents,
checkpoint, fees and change checks still govern preparation. No automatic or
incremental account synchronization is claimed. Native/backend/bridge unchanged.
