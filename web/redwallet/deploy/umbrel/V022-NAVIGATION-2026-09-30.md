# RedWallet 0.22 — public scan continuity

Prepared, not yet imported or published. Production remains public 0.21 / Caffeine22.

User reported that leaving the wallet during a funded receive test discarded
all scan progress. AccountReadPanel used component-local state and refs; both
route changes and visibility gating unmounted it.

The fix keeps a bounded, same-tab public session for each bridge actor and
previously authenticated account xpub. Completed results, their original timestamp,
last durably reserved receive address, scan bounds and an interrupted AccountReader
survive remount. Unlocking after route navigation restores the prior view. Background
and route changes still abort active requests, lock keys and invalidate payment
reviews. No keys, controllers, passwords or signing state enter this cache.

A paused scan keeps the existing five-minute observation expiry. A fresh refresh
continues to probe all discovery bounds; it displays the previous completed result
with its date/block, but invalidates spending until refresh completes. Restoration
does not renew freshness. Actor changes cannot reuse another actor's session.
Vault storage invalidation and confirmed payments clear sessions. Reload/close still
clears memory; this is not durable scan storage. Issued-address indices remain
persisted separately using the existing Web Locks reservation. No backend, bridge,
CSP, cryptographic, checkpoint or signed-payment protocol changes.

UI labels now distinguish Refresh account, explain why the new-address action is
not yet available, and remove obsolete claims that sending is disabled in this
revision. Public version increments to 0.22; the first-launch marker is unchanged.
