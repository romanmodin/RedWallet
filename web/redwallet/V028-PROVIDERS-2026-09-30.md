## Implementation

Settings→Network has default Built-in RedWallet service and My own Fulcrum,
actual adapter identity/status, host/port/TLS/HTTPS endpoint/adapter ID fields,
Test connection, tested Save, Return to built-in, persistent local selection,
and explicit optional home-service fallback. Backend public getProviderInfo
reports only public endpoint/upstream identity/checkpoint/header-derived tip time.
Every wallet route uses the selected adapter's typed actor. A separate adapter
keeps private credentials on its operator host/canister; no user configuration
changes the shared provider, no arbitrary URL/outcall proxy or method was added.

Provider acceptance checks pinned height961640/hash, two-hour chain timestamp,
exact entered upstream/HTTPS identity, and no backup >6blocks behind last healthy
height. Existing extended-header pin on the bridge stays intact. Routing guards
invalidate in-flight results and payment reviews; old signed receipts/discovery
stay saved. Unknown payments query existing ID before retry; failed lookup blocks
any retry and found original bytes avoid rebroadcast. CSP and all key/signature
rules remain unchanged. Explicit demo screens retain labeled mock fee estimates;
live fee failure never substitutes a simulated fee.

BUILTIN_BACKUPS is empty because no independent host/node is available. Unit
failover is verified; production redundancy and live independent-backup outage
handling are NOT claimed. Same home bridge selected through another canister does
not become an independent backup.
